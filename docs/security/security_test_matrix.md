## 1. 目的と基本方針
B2B受発注プラットフォーム「MESHu」において、現在ユーザー企業データがゼロ件のクリーンな状態を奇貨とし、以下の2系統から徹底的なセキュリティ診断を実施する。

1. **アプリ層（mshoss）**: マルチテナント間でのデータ分離、認可制御（IDOR防止）、なりすまし防止の検証。
2. **インフラ・OS層（meshu.org）**: インターネット境界における不要ポート開放、データベース（PostgreSQL）直接接続の遮断、Webサーバー情報隠蔽の検証。

### テスト 1-1: 他社案件詳細への直接参照（IDOR / 閲覧認可制御テスト）
- **検証概要:** 無関係な第3企業アカウントでログインした状態で、他社間（サンプル商事 ⇔ テスト販売）の取引詳細URLに直接アクセスする。
- **検証対象URL:**
  - 買手詳細: `http://mshoss:8080/buy/detail/57`
  - 売手詳細: `http://mshoss:8080/sell/detail/57`
- **検証コマンド:**
  ```bash
  python3 ~/share/mesh_tool.py --audit-url "http://mshoss:8080/buy/detail/57"
  python3 ~/share/mesh_tool.py --audit-url "http://mshoss:8080/sell/detail/57"
  ```
- **合格基準（安全）:**
  - HTTP `403 Forbidden` または `404 Not Found` が返り、他社の案件名、単価、企業名が一切画面に表示されないこと。
- **不合格判定（脆弱性）:**
  - HTTP `200 OK` で他社の見積金額（￥34,595等）や品名が表示される。

---

### テスト 1-2: 他社商談チャットへのアクセス制御（通信機密性テスト）
- **検証概要:** 他社間が商談を行っている非公開チャットルームへの閲覧および投稿を試行する。
- **検証対象URL:**
  - チャット画面: `http://mshoss:8080/chat/1`
  - メッセージ投稿: `http://mshoss:8080/chat/1/message`
- **検証コマンド:**
  ```bash
  python3 ~/share/mesh_tool.py --audit-url "http://mshoss:8080/chat/1"
  ```
- **合格基準（安全）:**
  - 過去ログが閲覧できず、アクセスが `403 Forbidden` で拒否されること。
- **不合格判定（脆弱性）:**
  - 他社の商談メッセージ履歴が閲覧できてしまう。

---

### テスト 1-3: 他社取引に対するなりすまし受注承諾（不正操作テスト）
- **検証概要:** 他社宛ての注文に対し、無関係な第3企業が直接受注承諾エンドポイントにPOSTリクエストを送信する。
- **検証対象URL:**
  - 受注承諾画面: `http://mshoss:8080/sell/order-accept/57`
- **検証コマンド:**
  ```bash
  python3 ~/share/mesh_tool.py --audit-url "http://mshoss:8080/sell/order-accept/57"
  ```
- **合格基準（安全）:**
  - `403 Forbidden` で処理が拒否され、他社のステータス変更ができないこと。
- **不合格判定（脆弱性）:**
  - 受注承諾フォームが表示される、または注文請書が第3企業名義で発行されてしまう。

---

### テスト 1-4: 不正パラメータ・境界値バリデーションテスト
- **検証概要:** 見積依頼や見積回答において、不正な値（マイナス単価、数量ゼロ、極端な長文、制御文字）がサーバー側で適切に検証・拒否されるかを確認する。
- **検証内容:**
  - 単価にマイナス値（`-1000`）を指定した見積回答POST
  - 数量に `0` または不正文字列を指定した発注POST
- **合格基準（安全）:**
  - Laravel のフォームリクエスト・バリデーションで弾かれ、HTTP `422 Unprocessable Content` または入力エラーメッセージが表示されること。

## 第2部：インフラ・OS層・外部露出監査（対象: 本番 meshu.org）

### テスト 2-1: 不要ポート外部露出スキャン（不要サービス遮断検証）
- **検証概要:** インターネット外部から `meshu.org` に対してポートスキャンを行い、不要な管理ポートや内部サービスが露出していないか確認する。
- **対象ポート一覧:**
  - `22/tcp` (SSH) - **開放想定**（要・公開鍵認証）
  - `80/tcp` (HTTP) - **開放想定**（常時HTTPSへのリダイレクト確認）
  - `443/tcp` (HTTPS) - **開放想定**
  - `21/tcp` (FTP) - **遮断必須**
  - `25/tcp` (SMTP) - **遮断必須**
  - `3306/tcp` (MySQL) - **遮断必須**
  - `5432/tcp` (PostgreSQL) - **遮断必須（最重要）**
  - `6379/tcp` (Redis) - **遮断必須**
  - `8000/8080/9000/tcp` (開発用・内部FastCGI) - **遮断必須**
- **検証コマンド（alisaツール）:**
  ```bash
  python3 ~/share/mesh_tool.py --audit-infra meshu.org
  ```
- **合格基準（安全）:**
  - 22, 80, 443 のみ OPEN、それ以外のポート（特に 5432: PostgreSQL）は `CLOSED` または `FILTERED` であること。

---

### テスト 2-2: PostgreSQLデータベース直接接続試行（外部DB侵入テスト）
- **検証概要:** 外部ホストから直接 `psql` コマンドで `meshu.org` の 5432 ポートへ接続を試行し、TCPハンドシェイクレベルで完全に拒絶されることを確認する。
- **検証コマンド:**
  ```bash
  nc -zv -w 3 meshu.org 5432
  # または
  psql -h meshu.org -U postgres -d meshu -W
  ```
- **合格基準（安全）:**
  - タイムアウト（接続拒否）となり、認証プロンプトすら到達しないこと（ファイアウォール/セキュリティグループによる完全防壁）。
- **不合格判定（脆弱性）:**
  - `Password for user postgres:` のプロンプトが返ってくる（認証突破によるDB全データ漏洩リスク）。

---

### テスト 2-3: Webサーバー情報漏洩 & セキュリティヘッダー診断
- **検証概要:** Webサーバー（Nginx / PHP）が自身の詳細バージョンをレスポンスヘッダーで外部に漏洩していないか、また主要セキュリティヘッダーが付与されているかを監査する。
- **検証対象ヘッダー:**
  1. `Server`: Nginxの詳細バージョン（例: `nginx/1.24.0 (Ubuntu)`）が隠蔽されているか（`server_tokens off;`）。
  2. `X-Powered-By`: PHPの詳細バージョン（例: `PHP/8.2.35`）が隠蔽されているか（`expose_php = Off`）。
  3. `Strict-Transport-Security` (HSTS): 常時SSLを強制しているか。
  4. `X-Frame-Options`: クリックジャッキング対策が施されているか。
  5. `X-Content-Type-Options`: MIMEスニッフィング対策（`nosniff`）が施されているか。
- **合格基準（安全）:**
  - サーバー・PHPの詳細バージョン番号が非表示化されていること。
  - 主要セキュリティヘッダーが付与されていること。

## 監査実行プロトコル（alisaへの指示方針）
1. **アプリ層監査の実行:**
   - `--status` で「株式会社サード・エンタープライズ」ログイン状態を確認。
   - テスト 1-1 〜 1-3 を実行し、他社案件データへのアクセスが確実にブロックされることを確認・記録。
2. **インフラ層監査の実行:**
   - `--audit-infra meshu.org` を実行し、ポート露出状況およびWebサーバー設定を自動診断。
3. **結果の整理と報告:**
   - 検出結果をレポートとして整理し、改善が必要な箇所（ヘッダー設定やNginx設定等）を開発者へフィードバックする。
